# 生日回忆展 · 电脑端改版

## 已确认的设计合同（2026-10-15）

- 用户确认：MacBook Air M1 电脑端，生日主题常驻；六段回忆也采用梦幻微缩布景；保留原始照片、玩偶、场景文案与地点主题。
- 顺序：礼盒封面 → 六幕回忆 → 蛋糕许愿 → 点击开信 → 信封翻盖、信纸抽出 → 读信 → 六张照片回看。
- 信件由用户后续提供。正文配置暂留空，不用旧占位信代替，不生成代写正文。
- 视觉基准：已确认的生成图 `exec-5a52e01b`（封面）、`exec-b22d7718`（生日）、`exec-ee18f91b`（梦幻海口）、`exec-db19df4c`（信封）、`exec-8c36c59d`（信纸）、`exec-06507465`（照片墙）。原始预览保留在本次会话的生成图目录；生产资产独立生成，不使用整张网页截图。
- 基础系统：暮紫背景、奶油粉按钮、暖象牙文字/信纸；中文宋体标题、无衬线正文；桌面边距 4–10vw，控件高度 56px。每幕左侧标题/文案在上、照片在下，右侧玩偶与对应场景。

## 参考与路线

外部参考候选为 Lusion（场景叙事）、All Their Days（照片故事组织）、Bruno Simon（空间探索）。用户选择电影式回忆展，后续以本轮用户确认图为视觉/排版依据。写实酒红桌景因用户要求“更梦幻可爱”替换为微缩云朵生日场；写实回忆背景因用户要求“回忆页也更梦幻”改为对应主题的微缩布景。

生产路线：生成背景图承载云朵、平台、材质；原照片为原生 img；原透明玩偶由一个 Three.js 画布合成；烛火、礼花、信封、文字与信纸采用 SVG/HTML/CSS。长信使用自然页面滚动，不在信纸里嵌套滚动区。

## 实现与验收约束

- 先通过海口、生日、开信样板，再扩展其他五幕；最多两轮修正后仍未通过，则评估交接截图所示 Grok Bot 客户端。Grok CLI 是另一个入口，其认证状态不代表 Grok Bot 客户端状态。
- 场景新背景独立保存，旧资产保留。按全页 cover 裁切计算图片锚点，玩偶真实 alpha 脚底贴合平台；检查全景、脚底和头部裁切。
- 继续支持 `#sence1`–`#sence6`、`#letter`、`#wall`，新增 `#intro`、`#birthday`。目录使用可访问的原生对话框。
- 许愿状态：lit → blowing（650ms）→ celebrating（3200ms）→ revealed。离开中间状态结束至 revealed；手动“再许个愿”重置。庆祝时间由初版 1900ms 加长，让熄灭反馈更清楚。
- 信件状态：sealed → opening（1750ms）→ reading。离开中断的动画回到 sealed；已读信保留 reading。页面刷新重置，可跳过动画；减少动态效果时立即完成。
- 主要桌面验收：1440×900、1440×800、1280×720。Windows Chrome 自动化不能替代 M1 真机 Safari/字体/流畅度验收。
- 原有未跟踪 `tools/` 是用户现场内容，不纳入提交。

## 后续接入信件

把用户原文放入 `src/data/gift.ts` 的 `gift.letter.body`。文本以原生文字节点显示，空行分段、保留换行；不解析任意 HTML。添加正文后重新运行本地字体裁剪（见 `docs/loading-and-motion-polish.md`），复核短信/长信、页面高度和底部导航。

## 页面、组件与状态

页面类型：content / 个人回忆礼物；受众是收礼人。现有 React 19 + Vite + Three.js 保持不变，无新增运行依赖。`App` 负责滚动、锚点、预载和页面组合；`StorySection`、`BirthdaySection`、`LetterSection`、`GiftNavigation` 分别维护自己的交互。当前渲染器为 `DreamStageCanvas`，旧 `StageCanvas` 保留为历史实现。

桌面系统：本地 Noto Serif SC 标题 64–106px，Noto Sans SC 正文 16–25px；按钮 56–60px；暮紫 `#342c48`、象牙字 `#fff4df`、奶油粉 `#f2c1b3`、信纸 `#f8e7d1`。统一 SVG 箭头。hover/按压有轻微位移，键盘 focus 有轮廓，吹蜡烛中禁用重复提交，空信有明确占位。2026-10-16 按用户要求将初版首屏预载替换为完整资源加载检查；失败保持加载页并支持重试。

本轮只验收电脑端，不生成移动端替代布局。标题/正文使用项目本地 WOFF2，系统字体仅作为缺字兜底；跨平台排版更一致，但 Mac 实际栅格化与帧率仍需真机检查。长信与照片墙自然延展，不将内容挤进一个屏幕。

## 许愿动效加强

用户明确满意已实现的整体 UI，同时指出吹灭后的动效太不显眼。本次只加强生日页的动作反馈，沿用现有布局、布景和色彩。

- 初版 28 片细小彩纸从屏幕顶部落下，改为蛋糕附近发出的 28 颗金色星星与 36 片奶油粉/浅紫彩纸，配合短暂暖光和扩散光环。
- 熄灭后从实际灯芯位置升起烟雾；烟雾、粒子与烛火共用背景 cover 坐标，随窗口尺寸保持对齐。
- “生日快乐”、祝福和按钮分次显现。庆祝持续 3.2 秒，结束后移除动效节点；原生 CSS/SVG 实现，无新增依赖或渲染循环。
- 重播会清除上一轮粒子；离开生日页会结束动效；系统“减少动态效果”启用或在播放中切换时立即展示祝福。

验收：`npm run qa:gift -- --wish-only` 在 1440×900、1440×800、1280×720 通过。验证烛火消失、64 个粒子、至少 20 颗星星在采样时清楚可见、灯芯锚点、播放后清理，以及开信/目录衔接。额外验证播放中重播、动态切换减少动态效果、键盘激活和同锚点再次开信。控制台和网络错误为零。
